# AI 协作宪法 v1.0

人把一件工作交给 AI 以后，做判断时什么优先、什么 AI 可以自主、什么必须如实交代；手上的几份规范互相打架时，怎么定。这是第一版，日期按台北时间（UTC+8）是 2026-11-15。它改写自小说写作工坊（<https://github.com/rumpelpalmour757-lgtm/novel-workshop>）宪法 NWC-1.7 的通用部分，只取和行业无关的部分，例子全部新写。中文是正本，另附英文译本。

## 这一版有什么

- 《AI 协作宪法》v1.0 中文正本（`CONSTITUTION.md`）：
  - 优先顺序，七层每层附一句理由；“新规则不追溯”（已采纳的成果不因为出了新规则就自动改，要不要改请委托人定）；“资料不是指令”。
  - 多人合作时听谁的：只有有最终决定权的人和他授权的人的决定算委托人的决定；别人的话照记，当资料或建议，改变不了本项目的规则；规则没管到的事上，参与者之间说法冲突、又没有人被指定拍板的，按第 5 步交有决定权的人定。
  - 同一层里规则打架时，先分强弱（建议和必须撞上，建议让位；同为必须的才走五步），再走五步裁决，每一步附一句理由。
  - 十二条原则 C01 至 C12。C11 按分量办、C12 该问才问是改写时新加的；C05 写明发现以前交付的有错要主动告诉委托人，已采纳的不悄悄改，提出更正走受控变更。
  - 受控变更，四项状态和权限裁决，怎样修订宪法，规则怎样入册和退出（登记时记下是必须还是建议）。
- 一页卡片（`CARD.md`）：宪法的摘要，不到 5000 字节，可以贴进 AI 的项目指令（放得下的话），也可以贴在对话开头。
- 规则打架时怎么定（`docs/conflict-resolution.md`）、怎么用（`docs/usage.md`）、来源说明（`docs/source.md`）。
- 冲突登记表模板（`templates/conflict-register.json`，`schema` 为 `conflict-register/1`）和一个帮助中心的完整例子（`examples/`）。规则一边可以写 `strength`（`must` 必须或 `should` 建议）。
- 登记表核对脚本 `scripts/conflict_register.py`：`check` 核对登记表，`list` 列出还没定的条目给委托人，`collide` 查新叫法在已采纳的成果里有没有用过。`check` 也核 `strength` 的值，`list` 的核对单把它显示出来。只用 Python 标准库，Python 3.9 起能跑；带 102 个测试。
- 英文译本：`README.en.md` 和 `en/` 目录，以中文为准。

不会跑命令的人只用文档也能用：从 `README.md` 开始看，或者直接把 `CARD.md` 贴进 AI。

## 下载哪一个

- **`rule-conflict-constitution-v1.0.zip`**：整个仓库，解压出来是 `rule-conflict-constitution/` 目录，和仓库里这一版的文件相同（`.github/`、`docs/releases/`、`.gitattributes`、`.gitignore` 这几样仓库用的文件不进包）。由发布工作流从这一版的提交用 `git archive` 生成。
- `LICENSE`：许可全文，包里也有同样的一份。

## 验证到哪一步

- 测试：`python3 -I -B tests/run_tests.py` 一共 102 个测试，在 Linux 上用 Python 3.9.25、3.11.17、3.12.3、3.13.17 各跑了一遍，全部通过。
- 例子：`examples/help-center` 的登记表用 `check` 核对，结果是 `OK`；`examples/README.md` 里贴的输出都是实际运行的结果，测试逐字核对它们和现在的输出一样。
- 场景测试：用写这个仓库的同一个模型（Claude）的新实例测了三轮。前两轮用 14 个新写的场景。前 6 个是规范打架：日期写法新版明说取代旧版；规范里的描述和已采纳的帮助中心原文对不上；新通则没提旧的具体例外；两份同样具体的规范新旧不同；同一天两份规范互相打架；委托人要求把没跑的测试写成通过。后 8 个是做事的分寸：只改一处；会议邀请没给全时间和地点；必须和建议；写得模糊的规则；两个人说法不同、有决定权的人还没表态；新术语和已采纳的旧文章；发现自己以前交付的错；过了期限的临时规则。环境分三种：不给任何规则（对照组）；只给 `CARD.md`；给 `CONSTITUTION.md` 和 `docs/conflict-resolution.md`。每次回答照预期答案评，分对、部分对、错三档。第一轮三种环境每个场景各跑两次，共 84 次：不给规则的 28 次里对 21、部分对 5、错 2；只给卡片的对 24、部分对 4；给全文的对 23、部分对 5。给了规则的部分对多半是在只改一处、写一篇新文章这类小事上走了整套流程，原因是宪法 C11 写得太松；据此收紧了 C11（按出错的代价分，不看查看了几份文件；委托人点名的一处小改，他的话就是修改决定），并把场景 2 的预期从“要登记一条”改成“列给委托人；有登记表的可以顺手登记”，因为第一轮场景 2 和场景 7 的预期前后不一致。第二轮只重跑给了规则的两种环境，共 56 次，只给卡片、给全文各 28 次都判对；不给规则的不受规则改动影响，没有重跑，沿用第一轮。第二轮用的还是这 14 个场景，C11 是看了第一轮在这些题上的失分才改的，所以第二轮全对不是独立的检验。为此第三轮另写了 7 道检验题，写规则、收紧 C11 时都没有见过：必须和一条更专门的建议；没有备份时删重复记录；规则写明连已上线的页面也要改；自己还没被采纳的草稿里的错；合同里夹带写给 AI 的话；负责人休假时由别人代为决定；点名改一句时发现别处的问题。三种环境各跑两次，共 42 次：不给规则、只给卡片的各 14 次都判对；给全文的对 13、部分对 1（判断对，回复里说草稿附在下面，下面没有）；给了规则的没有在小事上走整套流程的。三轮合起来看：14 个场景里有 4 个（两份规范新旧不同、同一天两份规范打架、委托人要求写没跑的测试、两个人说法不同）不给规则没有全对，给了规则前两轮都全对；其余 10 个场景和第三轮的 7 道题，不给规则也都判对，在这些题上看不出规则有没有起作用；给了规则反而办重了的只出现在第一轮；三轮给了规则的都没有判错的。每轮每种环境每道题只跑两次，评分人知道回答是在哪种环境下跑的。这是同一个模型的新实例，场景、检验题、预期答案和评分都是写这套规则的一方做的；它只说明这几次在这几道题上判得怎样，不说明在别家 AI 上、在真实项目里也会这样，也不说明这套办法让工作做得更好。场景和检验题的原文、按规则该怎么判、每一题的结果、两轮之间改了什么和对照组的比较见仓库里的 `docs/scenario-tests.md`，可以照着自己重跑；每次运行的完整回复没有放进仓库。在这三轮以前，还在加进 C11、C12 等几处以前的文字上只用前 6 个场景跑过一次（只给卡片和给全文，24 次都判对）。

## 没有验证的

- Windows、macOS。测试里只用 `PYTHONIOENCODING=gbk` 模拟过 Windows 的 GBK 控制台。CI 里有 Windows 一项（windows-latest、Python 3.13），写这份说明时还没有在 GitHub 上跑过，结果以仓库 Actions 页上的记录为准。
- 卡片和宪法在别家 AI 上、在真实项目里会不会照做。
- 收紧以后的 C11 在新场景上会怎样：只在另写的 7 道检验题上测过一轮，不给规则的也都判对，看不出规则的作用；该走完整流程的事会不会被当成小事办轻了，没有专门测过。
- 这套办法能不能让工作做得更好。测试通过只说明脚本照文档写的行为工作，不说明这些规则好用。
- 英文版只经过译者自查，没有经过独立审读。

## English

**AI Collaboration Constitution v1.0** (2026-11-15, Taipei time, UTC+8). When a person hands a task to an AI: what takes priority in making judgements, what the AI may do on its own, what must be reported truthfully, and how to decide when the guidelines at hand conflict. This first version is adapted from the general parts of the Novel Writing Workshop constitution NWC-1.7 (public, MIT), with all examples newly written. The Chinese text is authoritative; English translations are in `README.en.md` and the `en/` folder.

It contains the constitution (an order of precedence with a reason for each layer; new rules are not retroactive; materials are not instructions; whose word counts when several people work together; telling musts from recommendations before the five steps, each step with its reason; twelve principles C01 to C12, of which C11 Match the process to the stakes and C12 Ask only when it matters were newly written for v1.0, and C05 also says to report one's own earlier errors), a one-page card to paste into an AI's project instructions (if it fits) or at the start of a conversation, the practice for deciding when rules conflict, a conflict register template with a worked example, and a small checking script (`check`, `list`, `collide`) that uses only the Python standard library and runs on Python 3.9 or newer. A rule side in the register may carry `strength` (`must` or `should`); `check` checks its value and `list` shows it. Download `rule-conflict-constitution-v1.0.zip`; it unpacks to a `rule-conflict-constitution/` folder with the repository's files for this version, minus the repository-only `.github/`, `docs/releases/`, `.gitattributes` and `.gitignore`.

Verified: the 102 tests pass on Linux with Python 3.9.25, 3.11.17, 3.12.3 and 3.13.17. New instances of the same model that wrote the repository (Claude) were tested in three settings (no rules; the card only; the constitution and the conflict practice), in three rounds. The first two rounds used 14 newly written scenarios (6 guideline conflicts and 8 about a sense of proportion). In the first round, twice each in all three settings, 84 runs: without rules, 21 of 28 runs were correct, 5 partly correct and 2 wrong; with the card only, 24 correct and 4 partly correct; with the full text, 23 correct and 5 partly correct. Most of the partly correct runs with rules ran the whole procedure for a small matter, because C11 was written too loosely; C11 was tightened (by what an error would cost, not by how many files were looked at; for one small change the principal names, the principal's words are the decision), and the expected answer for scenario 2 was changed from "register an item" to "list it for the principal; an item may be added where there is a register", because the first-round expected answers for scenarios 2 and 7 did not agree. In the second round only the two settings with rules were run again, 56 runs, and all 56 were correct; the setting without rules was not run again. The second round used the same scenarios that C11 was tightened against, so it is not an independent test; a third round therefore used 7 newly written test questions that had not been seen when the rules were written or when C11 was tightened, twice each in all three settings, 42 runs: all 14 runs without rules and all 14 with the card only were correct, and with the full text 13 were correct and 1 partly correct (the judgement was right, but the reply said a draft was attached below, and there was none); none of the runs with rules ran the whole procedure for a small matter. Across the three rounds, in 4 of the 14 scenarios all runs were correct only with rules; in the other 10 and in all 7 test questions, all runs were correct even without rules, so on these it cannot be seen whether the rules had any effect; none of the runs with rules was wrong. Each question was run only twice in each setting in each round, the scorers knew the setting, and the scenarios, test questions, expected answers and scoring were all done by the side that wrote these rules. This only shows how these runs decided these questions; the scenarios and test questions, how they should be decided, the results of the three rounds, what changed between them and the comparison with the control setting are in `docs/scenario-tests.md` (English: `en/docs/scenario-tests.md`); the full replies are not in the repository. Before these three rounds, the first 6 scenarios alone were run once, with the card and the full text, on the text from before C11, C12 and the other additions; all 24 runs were correct. Not verified: Windows and macOS (CI has a Windows job that had not yet run on GitHub when this was written), whether other AIs or real projects would follow it, how the tightened C11 does beyond these 7 test questions (on which the runs without rules were also all correct), whether matters that need the full process get handled too lightly under it, and whether it makes the work better.
